# Zenodo deposits: structure and provenance

The original deposit (10.5281/zenodo.18974237) mixed code, official data and exploratory material in a
single "Dataset". For the revised version, publish **three separate deposits**, each with its own
`provenance.json` (generated by `make_manifest`).

| Deposit | Zenodo type | Contents | `--category` |
|---|---|---|---|
| Software | Software (GitHub -> Zenodo release, uses `CITATION.cff`) | tagged release of this repository | n/a |
| Official dataset | Dataset | only the `.h5` files that back tables/figures of the paper, plus `provenance.json` | `official` |
| Exploratory material | Dataset | development runs (other masses, `dt`, thresholds...), clearly labelled as not part of the paper | `exploratory` |

## Generating the manifest

```bash
python -m bav_dqs.utils.runtime.make_manifest \
    --data_file results/dirac_simulation_<stamp>.h5 \
    --paper-ref "Table I" --category official \
    --out deposit/provenance.json
```

For each file the manifest records: SHA-256, size, schema version, the full resolved config embedded
in the file, config SHA-256, Git commit and dirty flag, and per-width run attributes
(`edge_window`, `edge_persistence`, `richardson_order_p`, thresholds, hit indices).
`provenance_complete: false` flags files produced before provenance capture existed.

## Checklist before publishing a deposit

- [ ] `git_dirty` is `false` in every official file (results generated from a clean, tagged commit).
- [ ] The `config` embedded in each file matches the config shipped in the repository for that table
      (e.g. `configs/paper_table1.yaml`).
- [ ] Every official file has a `paper_ref` (table or figure) in `provenance.json`.
- [ ] Exploratory files are in their own deposit and not cited as results of the paper.
- [ ] `CITATION.cff` has the new version, DOI and release date.
